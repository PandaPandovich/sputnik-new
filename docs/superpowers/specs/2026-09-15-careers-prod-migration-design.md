# Миграция страницы «Работа в клинике» на прод — дизайн-спецификация

**Дата:** 2026-09-15
**Тема:** Sputnik Plus (WordPress)
**Окружение:** локаль — wp-env (`/Volumes/Webwork/sputnik-vet`), прод — деплой через `git pull` на сервере

## Цель

Перенести на прод шесть новых блоков страницы вакансий, саму страницу
«Работа в клинике» и форму отклика Contact Form 7 — так, чтобы контент на
проде совпал с локальным, а не был пересобран заново.

## Ключевая проблема

ACF хранит в атрибутах блока **числовые ID**, а не слаги. Штатный WXR-импорт
WordPress ремапит `post_parent` и `_thumbnail_id`, но **не** ID внутри
атрибутов блоков. Перенос `post_content` как есть дал бы на проде hero без
фото, четыре битых иконки и надпись «Форма отклика не выбрана в настройках
блока».

Отсюда требование: перенос обязан **резолвить ссылки по слагам** и **падать с
ошибкой** на нерезолвленном, а не публиковать страницу с дырами.

## Решение

Пара WP-CLI-скриптов в `tools/`, обменивающихся коммитимым JSON.

### `tools/export-careers-page.php` (локаль)

1. Берёт страницу по слагу `vacancies`, разбирает `parse_blocks()`.
2. Для каждого ACF-блока обходит `attrs.data` и заменяет:
   - значение поля типа `image` → `{{att:<post_name вложения>}}`;
   - значение поля `form` блока `sputnik/vacancies` → `{{cf7:<post_name формы>}}`.
3. Пишет `tools/data/careers-page.json`:
   ```json
   {
     "title": "Работа в клинике",
     "slug": "vacancies",
     "blocks": "<сериализованная разметка с плейсхолдерами>",
     "media": [
       { "slug": "zabota-o-komande", "title": "Забота о команде", "file": "careers-care.svg", "bundled": true },
       { "slug": "close-up-veterinarian-taking-care-dog-2", "file": "2025/06/close-up-veterinarian-taking-care-dog-2-scaled.jpg", "bundled": false }
     ],
     "forms": [ { "slug": "vacancy-application" } ]
   }
   ```
   `bundled: true` — исходник лежит в `tools/icons/` и может быть залит
   импортёром, `title` нужен ему для заголовка вложения; `bundled: false` —
   файл ожидается уже в медиатеке прода, `file` указан справочно, чтобы было
   понятно, что именно искать при расхождении.
4. JSON коммитится в репозиторий: перенос становится воспроизводимым и
   переживает повторный прогон на staging.

### `tools/import-careers-page.php` (прод)

1. Читает `tools/data/careers-page.json`.
2. Резолвит `{{att:слаг}}`:
   - ищет вложение по `post_name`;
   - не нашёл и `bundled: true` → сайдлоадит файл из `tools/icons/` и **явно
     проставляет `post_name` через `wp_update_post()`**;
   - не нашёл и `bundled: false` → копит в списке недостающего.
3. Резолвит `{{cf7:слаг}}` → форма по `post_name`; не нашёл → ошибка
   «сначала запустите `create-vacancy-form.php`».
4. Если список недостающего непуст — `WP_CLI::error` с перечнем слагов.
   Страница не создаётся и не обновляется.
5. Создаёт страницу со слагом `vacancies` в статусе **`draft`**; при повторном
   запуске обновляет только `post_content` и `post_title`, статус не трогает.
   Запись через `wp_slash()` — иначе экранирование `\n` в JSON-атрибутах
   блоков потеряет обратный слэш.

Явная простановка `post_name` в п. 2 — обязательна: плагин `cyr2lat` активен,
и слаг, выведенный из русского заголовка, получится транслитерированным
(`zabota-o-komande`), а не совпадающим с плейсхолдером.

## Порядок выкатки

1. **Пред-проверки прода:** WP ≥ 6.8 (иначе сработает ветка отката регистрации
   блоков), ACF PRO ≥ 6.x, Contact Form 7 активен, SVG Support активен,
   `upload_max_filesize` и `post_max_size` ≥ 10 МБ (форма принимает резюме до
   10 МБ), страница `politika-konfidencialnosti` существует (на неё ссылается
   чекбокс согласия).
2. `git push` в `main` → `git pull` на проде.
3. `wp eval-file wp-content/themes/sputnik-new/tools/create-vacancy-form.php`
4. `wp eval-file wp-content/themes/sputnik-new/tools/import-careers-page.php`
5. Визуальная проверка черновика через предпросмотр.
6. Публикация страницы вручную.
7. Добавление пункта в меню.
8. Сброс кэша (страничного и OPcache).

## Проверка результата

- Все шесть блоков рендерятся, вёрстка не разъехалась.
- Фильтр по направлениям переключает карточки, «Все» показывает все четыре.
- Клик по карточке открывает модалку с описанием вакансии.
- «Откликнуться» переключает модалку на форму, заголовок содержит название
  вакансии.
- Кнопка «Отправить резюме» в CTA-баннере открывает ту же форму с заголовком
  «Отправить резюме» и без привязки к вакансии.
- Форма отправляется, письмо приходит на админский адрес, приложенное резюме
  доходит, `Reply-To` указывает на кандидата.
- Форма не обёрнута лишними `<p>` (проверка `wpcf7_autop_or_not`).
- Блок «Наша команда» показывает трёх сотрудников с фото из настроек темы.

## Осознанно принятые решения

- **Почта отклика** остаётся `[_site_admin_email]`, отдельный HR-ящик не
  заводим.
- **Yoast-мета** страницы не заполняется — Yoast сгенерирует автоматические
  title и description.
- **Кнопка «Познакомиться с командой»** в блоке «Наша команда» остаётся с
  `href="#"`. На опубликованной странице это неработающая ссылка; поправляется
  в редакторе в любой момент. (У кнопки CTA `href="#"` намеренный — клик
  перехватывает `view.js` блока вакансий.)
- **Полный дамп БД (AI1WM) не используется** — он затёр бы прод целиком.
- **Фото hero и CTA не кладутся в репозиторий.** Ожидается, что они уже есть в
  медиатеке прода: локальная БД — клон прода, файлы датированы 2025/06 и
  2026/05. Если импортёр их не найдёт, он скажет об этом явно и остановится.

## Риски

| Риск | Проявление | Реакция |
|---|---|---|
| Слаг фото на проде отличается | Импортёр падает со списком недостающих слагов | Загрузить файл вручную с нужным слагом либо поправить `media` в JSON |
| ФИО сотрудников на проде отличаются от локальных | Блок «Наша команда» рендерится без карточек | Сверить три ФИО до выкатки; при расхождении перевыбрать в редакторе |
| WP на проде < 6.8 | Блоки регистрируются веткой отката | Проверить версию на шаге 1; ветка отката рабочая, но лучше знать заранее |
| Лимит загрузки прода < 10 МБ | Резюме крупнее лимита не отправляются | Проверить на шаге 1, при необходимости поднять лимит или снизить `limit` в форме |

## Откат

- **Код:** `git revert` коммита + `git pull` на проде.
- **Контент:** страница остаётся черновиком до явной публикации, поэтому откат
  сводится к возврату в черновик или переносу в корзину. Форма CF7 и четыре
  иконки безвредны сами по себе и удаляются вручную при необходимости.
