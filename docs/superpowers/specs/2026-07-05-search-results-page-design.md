# Страница результатов поиска — дизайн-спецификация

**Дата:** 2026-07-05
**Тема:** Sputnik Plus (WordPress)
**Макет:** фрейм `B9z59N` в Pencil (`untitled.pen`)

## Цель

Реализовать страницу результатов поиска по макету. Поиск должен покрывать не
только штатные записи (статьи, отделения), но и **врачей** и **услуги**,
которые хранятся как ACF-поля в опциях темы. Карточки врачей и услуг сами по
себе никуда не ведут — на них расположена кнопка «Записаться» (ссылка `tel:`,
как на других страницах сайта).

## Контекст (что уже есть)

- Формы поиска в хедере (`header.php`) шлют `GET` на `home_url('/')` с полем
  `name="s"` → штатный поисковый запрос WordPress `?s=`.
- В `src/js/main.js` есть обработчик, который сейчас делает `preventDefault()`
  на submit формы хедера, поэтому по Enter/кнопке страница результатов **не
  открывается**. Живой AJAX-дропдаун (`action=sputnik_search`) остаётся.
- Шаблон `search.php` **отсутствует** — сейчас `?s=` уходит в `index.php`
  (`get_header(); the_content(); get_footer();`), который для поиска ничего
  осмысленного не выводит.
- Телефон для записи: `get_field('footer_phone', 'option')` (используется в
  `footer.php`, нормализуется `preg_replace('/[^\d+]/', '', ...)`).
- SCSS-партиалы подключаются через `@forward './parts/xxx.scss';` в
  `src/scss/main.scss`.

## Источники данных

Все результаты объединяются в единый нормализованный список. Четыре категории
(совпадают с фильтром в макете: Все / Услуги / Статьи / Клиники / Врачи):

| Категория | `type` | Источник | Поля для поиска | Ссылка карточки |
|---|---|---|---|---|
| Услуги | `service` | опции `price_categories` → вложенный репитер `prices` | `price_category` (название услуги), `desc`, имя категории `name`, заголовок отделения `department` | нет → кнопка `tel:` |
| Статьи | `article` | `WP_Query` `post_type=post`, `s=` | штатный поиск WP | пермалинк поста |
| Клиники | `branch` | `WP_Query` `post_type=branch`, `s=` | штатный поиск WP | пермалинк отделения |
| Врачи | `doctor` | опции `team_members` | `name` (ФИО), `specialization`, `tag`, `branch`, `description` | нет → кнопка `tel:` |

Структура ACF (подтверждена по `acf-json/`):

- **Команда** (`options_page: theme-settings-team`), группа `group_684b2c3d4e5f6`:
  репитер `team_members` с подполями `name`, `specialization`, `photo`, `tag`,
  `branch`, `description`.
- **Цены на услуги** (`options_page: theme-settings-prices`), группа
  `group_684a1b2c3d4e5`: репитер `price_categories` с подполями `department`
  (post_object), `name`, и вложенным репитером `prices` (`price_category`,
  `price`, `desc`).

Тип `page` в поиск **не включается** (в макете нет такого фильтра).

## Компоненты

### 1. `sputnik_collect_search_results( $query )` — в `functions.php`

Чистая функция сбора и нормализации. Возвращает массив элементов вида:

```php
[
  'type'       => 'service'|'article'|'branch'|'doctor',
  'type_label' => 'Услуга'|'Статья'|'Отделение'|'Врач',
  'icon'       => '<svg ...>',   // иконка по типу (по макету)
  'title'      => string,
  'breadcrumb' => string|null,   // для услуг: отделение / категория; для статей: дата и т.п.
  'excerpt'    => string|null,   // краткое описание
  'url'        => string|null,   // null для doctor/service
  'price'      => string|null,   // только service
  'bookable'   => bool,          // true для doctor/service → кнопка tel:
]
```

Логика:

- **Статьи / клиники:** `WP_Query( [ 'post_type' => 'post'|'branch', 's' => $query, 'posts_per_page' => -1, 'post_status' => 'publish' ] )`.
- **Врачи:** `get_field('team_members', 'option')`, фильтрация строк через
  `mb_stripos` (регистронезависимо, кириллица) по перечисленным полям.
- **Услуги:** `get_field('price_categories', 'option')` → перебор категорий и
  вложенных `prices`; каждая совпавшая услуга → отдельный результат с ценой и
  breadcrumb (отделение / категория). Совпадение по названию услуги, описанию,
  имени категории или заголовку отделения.
- Все текстовые совпадения — через `mb_stripos`.
- Дедупликация (пост может попасть один раз).

### 2. `search.php` — шаблон

- `get_header()`, затем разметка страницы, `get_footer()`.
- Читает запрос через `get_search_query()`.
- Зовёт `sputnik_collect_search_results()`, считает счётчики по категориям.
- Рендерит:
  - Заголовок «Результаты по запросу «<запрос>»».
  - Счётчик «Найдено N результатов» с корректным склонением
    (результат / результата / результатов) — helper для плюрализации.
  - Сайдбар-фильтр: чипы Все / Услуги / Статьи / Клиники / Врачи со счётчиками,
    у каждого `data-filter="<type|all>"`.
  - Список карточек `.search-result` с `data-type="<type>"`: иконка, лейбл типа,
    breadcrumb, заголовок, описание; для услуг — цена; для статей/клиник —
    ссылка/стрелка перехода; для врачей/услуг — кнопка «Записаться»
    (`<a href="tel:...">` из нормализованного `footer_phone`).
  - Пустое состояние (нет результатов вообще) — в стиле существующего блока
    «Ничего не нашлось» с кнопкой связи.
- Карточка без `url` рендерится как `div`, а не `a`.
- Экранирование всего вывода (`esc_html`, `esc_url`, `esc_attr`).

### 3. `src/scss/parts/search.scss`

Стили страницы по макету (шапка результатов, сайдбар-фильтр, карточки разных
типов, цена, кнопка записи, пустое состояние, адаптив). Подключить через
`@forward './parts/search.scss';` в `main.scss`.

### 4. JS в `src/js/main.js`

- **Клиентская фильтрация:** клик по чипу фильтра → снять `active` с прочих,
  выставить на текущем; показать/скрыть `.search-result[data-type]` согласно
  выбранной категории (`all` — показать все); обновить активное состояние и
  пустое состояние для конкретной категории («В этой категории ничего нет»).
  Счётчики берутся из отрендеренной разметки.
- **Правка submit хедера:** разрешить нативную навигацию формы на `?s=`
  (по Enter и по кнопке), сохранив живой AJAX-дропдаун при наборе. Заменить
  безусловный `preventDefault()` на логику, которая не блокирует переход на
  страницу результатов.

## Поток данных

```
Хедер (submit ?s=) → WordPress роутит на search.php →
sputnik_collect_search_results($q) → нормализованный список →
рендер всех карточек + счётчики → клиентская фильтрация (без перезагрузки)
```

## Крайние случаи

- Пустой запрос или ноль результатов → общее пустое состояние.
- Врач/услуга без URL → `div`, не ссылка; кнопка `tel:`.
- `footer_phone` пустой → кнопка ведёт на запасной телефон/скрывается
  (нормализация как в `footer.php`).
- Кириллица → везде `mb_*`.
- Склонение «результат/результата/результатов» и «врач/врача/врачей» и т.п.
- Дедупликация результатов.
- XSS: экранирование всего пользовательского вывода.

## Тестирование

Автотестов/линтеров в проекте нет (`npm run build` для сборки ассетов).
Ручная проверка:

1. Enter в поиске хедера → открывается `search.php` (не index).
2. Запросы «вакцин», «терап», ФИО реального врача → релевантные карточки в
   нужных категориях.
3. Каждый фильтр сайдбара показывает только свою категорию; «Все» — всё.
4. Счётчики корректны и склоняются.
5. Кнопка «Записаться» на враче/услуге = `tel:` с телефоном из настроек.
6. Карточки статей/отделений ведут по ссылке; карточки врачей/услуг — нет.
7. Пустой запрос и запрос без результатов → пустое состояние.
8. `npm run build` проходит, стили и JS подключаются.

## Вне рамок (YAGNI)

- Расширение AJAX-дропдауна хедера на врачей/услуги (сейчас только
  posts/pages/branch/services) — отдельная задача, здесь не трогаем.
- Пагинация — все результаты на одной странице (объём данных клиники мал).
- Серверная фильтрация по URL-параметру — выбрана клиентская.
- Реальная форма записи — используется `tel:`-ссылка, как на других страницах.
